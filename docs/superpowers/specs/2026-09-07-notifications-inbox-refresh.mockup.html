Where it stands

The inbox today is a tinted card that says what happened but not to what

Screenshots from dev.ntizo.co.mz, 7 Sep 2026. Almost every row is unread, so the pale-blue tint that was meant to mark the odd unread row becomes the whole page. Each row names a type of event and a time, and nothing else: which booking was closed, which conversation has a message. Clicking a row only marks it read.

  • No card, no tint

    The list sits on the white page as hairline rows, the same construction as the provider rows on the listings refresh. Unread is a navy dot and a heavier title, which is what people actually scan for.

  • A second line that names the thing

    Booking notifications already carry the service, the provider, the date and the price in their payload. The row now says them, so "a booking was closed" becomes "Pintura de sala · Pinturas Nhaca · 27 Aug".

  • Rows go somewhere

    A notification about a booking opens that booking; one about a message opens that conversation. Marking read happens on the way. Rows with nowhere to go (welcome, verified) still mark read on click.

  • Mark one, on hover

    Because the row now navigates, marking a single row read gets its own small control, shown on hover and focus for unread rows only. Mark all becomes a text action beside the count instead of an outlined button.

  • Times that fit their group

    Today and yesterday show the clock; earlier rows show the date, since the group spans weeks. Sentence-case group labels in navy replace the tracked all-caps ones.

  • A loading state that holds its shape

    The page currently renders nothing until the first page lands, then jumps. Three placeholder rows at the real row height stand in for it, the same trick the activity list already uses.

Unread is the dot, not a ground. The dot column is 14px and empty on read rows, so titles stay on one vertical line whatever mix of read and unread the list holds. The icon disc borrows navy on unread rows and drops to grey on read ones; nothing is tinted.

The context line is what the payload can honestly say. Bookings carry serviceName, providerName (or the customer's first name on the provider side), startsAt, priceMinor. The price is shown only on the row that asks for payment. Messages and support threads carry only a thread id and a subject, so their second line is the action ("Abrir a conversa"); a sender name there needs the backend to put one in the payload, which this change does not do.

Clicking a row opens its target and marks it read. Bookings go to /bookings/$bookingId, messages and support to /messages?thread=…; in the provider zone the same map points at /provider/$slug/…. The mark-read control on hover is for the reader who wants to clear a row without opening it.

Mark all is a text action. It appears only when something is unread, exactly as today, but as navy text with an underline on hover rather than an outlined button competing with the heading.

Same list in the provider zone. NotificationsPage is shared; the workspace inbox inherits every change and keeps its own heading "Notificações do negócio" inside the console shell.

What changes

Files, if this is approved

Built on dev in its own worktree, since this branch is 202 commits behind it and dev already has the infinite-scroll inbox. Figtree and the navy tokens arrive with the listings refresh; until it merges the page reads its headline colour with a fallback to the current ink and inherits whatever the display font is, so it degrades to today's Poppins without a second change later.

FileChange
domain/notification-target.tsNew. Type + payload + scope → the route a row opens, or none. Bookings → the booking page in the reader's zone; messages and support → the messages page with ?thread=.
domain/notification-detail.tsNew. Type + payload + locale → the context line, or none. Reads the booking payload's service, counterpart name, start time and, for the payment row, the price.
domain/inbox-groups.tsGains formatWhen(createdAt, group, locale): clock for today and yesterday, day for earlier.
ui/notification-cell.tsxRewritten: a Link when there is a target and a button when not; dot column, hairline disc, title, context line, time, and the hover mark-read control with its own accessible name.
ui/inbox-list.tsxSentence-case navy group headings; hairline rows instead of the bordered card.
ui/inbox-skeleton.tsxNew. Three placeholder rows at row height for the first load.
ui/notifications-page.tsxHead with the unread count from useUnreadCount, mark-all as a text action, skeleton while pending, footer as caption + text link, empty state unframed.
ui/account-nav.tsxOptional: loses its card border on desktop, active entry in navy. Shared by all settings pages.
locales/*/notifications.jsonEight locales gain unreadCount (+_other), markRead, openConversation.
TestsUnit tests for the two new domain maps and formatWhen; cell tests for link vs button and the mark-read control; existing page tests updated for the new head and footer.
